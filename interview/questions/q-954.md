# 为什么要使用KV Cache？

## 答案

自回归生成每一步都会关注历史 token。因果注意力下，历史 token 的每层 K/V 不随后续 token 改变，可以缓存；新一步只需计算新 token 的 Q/K/V，再用新 Q 与已有 K/V 做注意力。

这样避免每次重跑整个历史前缀，但仍需要读取历史缓存。上下文越长，decode 的内存带宽和缓存占用通常越重要；prefill 与 decode 的瓶颈也可能不同。

标准缓存容量约为 `2 × 层数 × token数 × KV头数 × 头维度 × 每元素字节数`，批量与并发序列还会增加总量。GQA/MQA 减少 KV 头，MLA 改变缓存表示；实际容量另有分页和运行时开销。

缓存以额外显存换取较低重复计算成本，并不是免费加速。相同前缀复用也须匹配模型、位置与模板，涉及权限的内容要隔离。
