# 3．为什么探索 MoE 架构， MoE 相比 Dense 有什么好处

## 答案

**MoE 让每个 token 只激活少数专家，以较小的激活计算量使用更多总参数。** 通常把 Transformer 的 FFN 换成多专家层，router 根据 token 表示选择 top-k 专家并加权汇总，注意力等模块往往仍是共享的。
相对 Dense，MoE 可以在相近激活 FLOPs 下增加容量；专家也可能产生分工。但总参数依旧需要存储或分片，不能用“激活参数少”推导出总显存小。
主要成本是负载不均、专家通信、容量与丢 token 策略、路由稳定性和部署复杂度。选型要比较同预算下质量、吞吐、尾延迟与硬件利用率。
