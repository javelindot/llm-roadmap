# 项目：模型部署用了什么框架（vLLM/TGI/自研）？如何优化推理延迟和吞吐？

## 答案

先按真实项目说明框架、版本、模型、硬件和业务约束。vLLM 常用于高并发生成服务；TGI 或自研方案需要评估对应版本的模型支持、运维和接口需求，不能只按框架名称判断快慢。

优化前分别测排队、prefill、decode、工具和网络耗时，并记录输入输出长度及并发。针对瓶颈调整 continuous batching、KV Cache、prefix cache、量化、并行、最大上下文和调度参数。

减少无用上下文和输出 token 往往比盲目增加并发有效。缓存须包含模型、模板、租户和知识版本，避免跨用户泄露；量化需要回归质量与工具参数准确性。

在相同请求分布下比较 TTFT、每 token 延迟、P95/P99 完成时间、吞吐、显存与单位成本，并说明吞吐提升是否牺牲尾延迟。
