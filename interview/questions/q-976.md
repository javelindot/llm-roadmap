# DPO相比 SFT，有哪些优劣？它在 Agent 任务上效果提升明显吗？你怎么构造偏好对？构造逻辑是自动的还是人工？

## 答案

SFT 学习给定输入下的示范答案；DPO 用 chosen/rejected 偏好对调整相对概率，同时以参考模型约束变化。DPO 通常无需在线 rollout 和单独的奖励模型，但质量依赖偏好数据，且离线样本可能覆盖不到新策略的失败路径。

Agent 的偏好应覆盖**可核验任务结果和动作轨迹**：授权工具选择、参数正确性、任务成功、安全、延迟与成本。只偏好更流畅的最终文本，未必改善工具执行。

构造数据时，对同一任务生成多个候选轨迹，用确定性结果校验、人工评审或经过校准的裁判排序；隔离不同租户与测试集，拒绝把越权成功当成好样本。

是否优于 SFT 必须在相同模型、任务集与预算下比较成功率、权限违规率、工具次数和 OOD 表现。没有完成这样的实验，不应声称提升明显。
