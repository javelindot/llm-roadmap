# 好的，想象一个场景。我们希望打造一个产品，用户做广告不再是过去哪个先建广告组、做素材、定目标···而是交给 agent，用户只需要输入商品和基本信息，其他交给 agent 去做。那在这个过程中，main agent 发出指令，subject agent 执行。如果 subject agent 认为需要再做一个素材，这个过程应该如何流转？这个关系你会如何思考设计？

## 答案

**核心是让子 Agent 返回明确的状态和需求，由主 Agent 统一调整计划。** 子 Agent 不应自行无限创建新素材或扩大广告预算。

### 流转设计

主 Agent 下发目标、预算、截止时间和素材验收规则。子 Agent 若发现素材不足，返回 `needs_input`，附原因、所需素材类型、成本估算和已有证据；主 Agent 决定复用旧素材、调用素材生成服务、重新分配任务或请求用户确认。

子任务使用 task_id、parent_id、版本和幂等键记录状态。新素材通过合规、品牌与质量检查后回到原任务，主 Agent 再推进投放。把生成素材与实际发布广告分成独立动作，发布需要单独授权。

### 避免循环

为每个子任务设置重规划次数、总成本和截止时间；相同需求重复出现时转人工。验收看素材通过率、重复生成率、任务完成率和预算偏差，不能只看 Agent 是否回复了「完成」。
