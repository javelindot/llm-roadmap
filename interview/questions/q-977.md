# 你说你服务部署在 vLLM 上，为何选择它？KV-cache 如何帮助推理加速？你自己做过哪些优化？

## 答案

选择 vLLM 的理由应结合实际约束，例如兼容所用模型、并发生成能力、KV 管理、部署方式和可观测性。说明具体版本及与基线的测量结果，不能把框架宣传当成项目数据。

KV Cache 在 decode 时复用历史 K/V，避免重算前缀；代价是显存增长和长上下文的缓存读取。PagedAttention 通过分块管理减少浪费，continuous batching 动态安排请求。

可以开展的优化包括缩短输入、限制输出、调整批处理与并发、授权范围内的前缀缓存、量化、并行与排队限流。每项应验证质量、成本和尾延迟，而不只记录 tokens/s。

项目回答按「原瓶颈 -> 改动 -> 相同负载对比 -> 副作用」说明；没有自己实现算子时，应准确区分配置调优与底层开发。
