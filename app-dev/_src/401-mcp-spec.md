本章按 **2026-07-28** 规范解释通信模型，核对日期为 2026-10-12。不同年代的初始化、服务端请求和取消机制不能拼成一个实现。

## JSON-RPC 与身份关联

MCP 使用 UTF-8 JSON-RPC，带 id 的请求对应响应，通知不要求响应。协议 id 关联一次调用，不替代业务动作幂等键。

以下只是响应信封示例，不是完整 MCP 请求：

```json
{"jsonrpc": "2.0", "id": 1, "result": {"content": [{"type": "text", "text": "demo result"}]}}
```

请求版本、能力及其他元数据由支持对应规范的 SDK 生成，并用原始报文契约测试确认，不能省略后当作完整新版请求。

## 新旧通信模型

| 维度 | 较早连接级规范 | 2026-07-28 |
|------|----------------|------------|
| 版本与能力 | initialize 握手建立连接级信息 | 每个请求通过 _meta.io.modelcontextprotocol/* 携带 |
| 消息方向 | 允许规范定义的服务端请求 | 服务端不发起 JSON-RPC 请求，客户端不发送 JSON-RPC 响应 |
| 生命周期 | 初始化后工作，按传输关闭 | 请求与绑定的生命周期，按版本规则兼容回退 |
| 元数据 | 部分连接或传输字段 | 消息体为源，绑定可映射指定字段到信封 |
| 取消 | 旧版协议与传输约定 | stdio 通知取消，HTTP 关闭对应响应流 |

只把 initialize 的日期改成新日期不能完成迁移。较早 sampling/createMessage 等服务端请求，需要按新版能力机制和 SDK 支持重新集成。

## 标准传输

### stdio

客户端启动子进程，用标准输入输出交换换行分隔的 JSON-RPC。标准输出只承载协议，日志放标准错误；进程生命周期和资源限制由宿主控制。

不开端口不等于没有风险。子进程仍可能拥有文件、网络和环境凭证，需要控制运行目录、依赖与权限。

### Streamable HTTP

每个消息通过 HTTP POST 发往单一 endpoint，响应为 JSON 或请求范围内的 SSE 流。SSE 仍用于流式编码，不能说新版完全取代 SSE。

关闭流表达放弃当前请求，不证明外部副作用回滚。重试要保留业务操作键并核对真实结果。

绑定可映射版本与能力到 HTTP 头，但消息体仍为元数据源。精确头名、认证、错误和恢复以固定版本规范为准。

## 能力与授权

工具、资源和模板提供操作、材料与预定义内容；能力声明不赋予用户业务访问权。发现后记录服务身份、工具名、schema 与版本，每次调用重新检查权限。

远程 description 和资源正文属于外部输入，不能覆盖可信指令。资源 URI 不等于文件读取授权。

## 错误与进度

区分 JSON-RPC 错误、工具执行错误、业务拒绝和外部结果未知。扩展错误使用所选规范和 SDK 的真实类型，不能自行编造通用错误码。

进度不是成功回执，最终结果要与请求、业务动作和证据关联。对外只返回稳定错误，内部异常和凭证不能直接交给模型。

## SDK 版本边界

后续 FastMCP、ClientSession.initialize 示例展示连接级 SDK 形态，没有在本仓库验证 2026-07-28 兼容。固定包版本并确认协议年代后再接入。

保留旧接口用于理解实现和迁移。新版部署按兼容矩阵验收 stdio/HTTP、元数据、取消、流式、断线与认证，不能仅凭 SDK 安装成功判断兼容。
