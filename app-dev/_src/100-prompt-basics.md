## 为什么 Prompt 是「核心抓手」

Prompt 明确任务、可用信息和输出契约，是应用开发的重要入口。复杂任务还依赖模型能力、可信数据、工具和运行时；提示词本身不能保证任务完成。

设计 Prompt 时，需要验证以下结果：

- **准确性**：是否答中要害、没幻觉
- **可用性**：输出能否被下游程序直接消费（JSON / 表格 / Markdown）
- **专业性**：行业 jargon 是否到位、术语是否准确
- **稳定性**：同一类任务的输出一致性（评测时这个最关键）

## 四要素：组织任务的起点

角色、目标、执行边界和输出格式可以帮助组织复杂任务。这是一种模板，不是每个模型或任务都需要的固定配方：

```
┌─────────────────────────────────────┐
│  角色 (Role)        + 设定身份与视角     │
│  目标 (Goal)        + 说清要做什么       │
│  执行方案 (Plan)    + 拆解步骤与边界     │
│  输出格式 (Output)  + 规定结构与字段     │
└─────────────────────────────────────┘
```

### 1. 角色 (Role)

角色可以提示视角与术语，但不提供真实资历、工具权限或事实证据。

```python
# ❌ 没有角色
帮我分析一下这段代码

# ✅ 有角色
你是有 10 年经验的 Python 性能优化专家
```

如果需要关注内存分配、循环复杂度和 I/O 阻塞，应把这些检查点写明，并提供测量数据，不能仅凭角色名称期待模型自动满足要求。

### 2. 目标 (Goal)

清晰告知**最终要达成的结果**，避免歧义。

```python
# ❌ 模糊
帮我看看这段 SQL

# ✅ 明确
找出这段 SQL 中导致全表扫描的语句，并给出索引优化建议
```

### 3. 执行方案 (Plan)

给模型明确的**步骤、逻辑、边界**，规范完成路径。

```python
请按以下步骤执行：
1. 先识别出所有 JOIN 语句
2. 检查每个 JOIN 字段是否有索引
3. 对缺失索引的字段，给出 CREATE INDEX 语句
4. 评估每个索引的存储成本（粗略估算）

约束：
- 只关注 PostgreSQL 14+ 的语法
- 不考虑分区表（暂不支持）
```

### 4. 输出格式 (Output)

指定**结构化输出**，让结果可直接被下游程序消费。

```python
请输出 Markdown 表格，包含 4 列：
| 字段名 | 是否缺失索引 | 建议 SQL | 预估存储 (MB) |

如果某字段无需索引，「建议 SQL」填「不需要」。
```

## 完整模板示例

下面这条 prompt 把四要素全部用上：

```python
你是 PostgreSQL 14+ 性能优化专家。

任务：分析以下 SQL，找出可能导致全表扫描的写法，并给出索引优化建议。

执行步骤：
1. 识别所有 WHERE / JOIN / ORDER BY 字段
2. 判断每个字段的索引情况
3. 对缺失的，输出 CREATE INDEX 语句
4. 评估索引对写入性能的影响

约束：
- 只考虑 PostgreSQL 14+ 语法
- 不考虑分区表
- 索引名格式: idx_{table}_{column}

输出格式：Markdown 表格
| 字段 | 索引缺失 | 建议 SQL | 写入影响 |

待分析 SQL：
{sql_here}
```

只提供 SQL 时无法确认已有索引或查询计划。完整实验还需表结构、索引定义、数据分布及 EXPLAIN 结果；缺少这些材料时，应标记待核验项。

## 用实验验证效果

在同一模型、数据和预算下比较基础提示与候选模板，报告以下指标：

| 维度 | 怎么检查 |
|------|----------|
| 格式有效 | 解析并验证字段，而不是只看起来像表格 |
| 内容正确 | 与可信材料及独立检查结果比较 |
| 缺失信息 | 不编造索引或查询计划，明确所需证据 |
| 重复执行 | 多次运行记录波动和失败类型 |
| 成本与时间 | 统计整个任务，包括补问、检索与重试 |

:::callout 💡
结构化模板是否改善结果，需要由自己的案例集证明。格式更整齐不代表事实更准确；没有任务、样本和基线，就不能声称固定提升倍数。
:::

## 何时不需要四要素

四要素是**复杂任务**的标配。简单任务可以省略部分：

| 任务类型 | 推荐结构 |
|----------|----------|
| 闲聊 / 翻译 | 只要目标即可 |
| 单步推理 | 角色 + 目标 |
| 文档生成 | 目标 + 输出格式 |
| 复杂分析 | 全部四要素 |
| 多步工作流 | 全部四要素 + 分步骤 |
