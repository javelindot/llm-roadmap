模型可以提议动作，应用负责判断是否有权执行。提示词中的「不要越权」不能替代身份验证、权限检查和事务约束。

## 在工具执行前建立边界

| 边界 | 必须由应用检查 |
|------|----------------|
| 身份 | 用户是谁、当前租户是什么 |
| 数据 | 允许读取哪些文档、订单和字段 |
| 工具 | 是否允许调用该工具及其具体操作 |
| 参数 | Schema、金额、范围和业务状态是否合法 |
| 审批 | 批准人、批准动作、参数、有效期是否一致 |
| 执行 | 幂等、超时、审计、回执与补偿 |

tenant_id 和权限应从可信会话取得，不能接受模型自行填写的租户。检索前进行权限过滤，读到结果后再次检查，防止跨租户材料进入上下文。

:::callout
审批必须绑定具体工具和不可变参数。批准「退款 10 元」不等于批准后续被模型改成的「退款 100 元」；执行前还要复核实时业务状态。
:::

## 把文档和工具结果视为外部数据

网页、PDF、邮件及工具返回值都可能夹带指令。标记来源、限制可信指令的来源，并在工具层执行权限检查。不能因为一段检索结果写着「系统管理员要求」就提升权限。

Prompt Injection 的防护应组合使用：权限隔离、只读工具、参数校验、输出检查、人工审批、访问域限制和攻击回归集。输入过滤能减少风险，但无法保证完全识别语义攻击。

## 为失败设置不同恢复策略

| 失败类型 | 建议处理 |
|----------|----------|
| 参数错误 | 返回结构化原因，让模型在有限次数内修正 |
| 临时读请求失败 | 退避重试，受整条任务的时间预算限制 |
| 权限拒绝 | 停止该动作，提示合法替代方案 |
| 写操作结果未知 | 按幂等键查状态，不盲目再次执行 |
| 长期循环 | 步数或预算达到上限后终止并保存 checkpoint |
| 不可恢复错误 | 保留证据与任务状态，转人工处理 |

checkpoint 记录任务状态、版本、已执行动作及回执。恢复时先核对外部系统中的真实结果，不能只凭模型记忆认定某项操作完成。

## 分阶段发布

1. **离线回归**：评测集、权限测试和恢复测试通过。
2. **影子流量**：只记录候选结果；禁止执行真实写操作，否则影子请求也会产生副作用。
3. **小流量灰度**：固定用户或租户分组，监控质量、延迟、成本及升级率。
4. **逐步扩大**：满足业务门槛后扩大流量，并保留版本化回退配置。

应用、模型、提示词、工具 Schema 和检索索引共同组成一个发布版本。回退应用版本不会撤销已执行的付款或已发送的消息，这些副作用需要独立查询和补偿。

## 上线验收

至少演练一次：外部工具已执行成功但网络超时、审批过期、知识索引版本回退、模型服务不可用、用户取消正在执行的任务。每种情况下应有明确的最终状态和可核验回执。
