知识系统的验收目标是“当前用户取得有效证据，并据此完成任务”。增加图检索、重写查询或 Agent 循环，都需要证明它改善了这个目标。

## 先做可信的数据生命周期

```text
文档解析与质量检查 -> 文档版本、来源、ACL、生效期
  -> 切片与索引版本 -> 授权范围内召回 -> 重排与证据装配
  -> 引用校验与回答 -> 变更、删除和撤权传播
```

引用至少能定位文档与版本、页码或段落、有效期、检索时间和证据片段。索引更新后保留历史出处以便审计，但历史引用仍须经过当前访问权限检查。

文档删除、权限撤销和政策失效要传播到向量索引、关键词索引、图摘要及缓存。只删除一个向量而保留社区摘要，仍可能泄露原文信息。

检索身份来自可信会话。尽量在召回前过滤，重排、装配和输出前再次检查。先全量检索再让模型过滤，可能已经把无权数据传给模型或日志。

## 三种架构的实验起点

| 架构 | 适合的问题 | 主要代价 | 对照基线 |
|------|------------|----------|----------|
| 两阶段 RAG | 必须先查政策或手册的问答 | 检索失败会影响后续回答 | 授权检索加引用回答 |
| Agentic RAG | 需要多轮探索、多来源补充 | 可变延迟、查询循环和工具误用 | 同工具范围的固定检索流程 |
| 混合 RAG | 可先检索，再有限补充并验证 | 路由与终止条件更复杂 | 固定一轮检索与显式拒答 |

这里的“混合 RAG 架构”不同于 BM25 加向量的“混合召回”；前者描述流程，后者描述检索算法。

## 研究方法的适用边界

| 方法 | 值得实验的情况 | 要额外检查 |
|------|----------------|------------|
| Contextual Retrieval | 片段脱离文档背景后含义不清 | 补充背景是否准确，索引更新与预处理费用 |
| Late Chunking | 需要利用长文中跨片段语境 | 模型是否提供所需 token 表征，长文上限 |
| GraphRAG | 跨实体关系或全局归纳问题 | 实体质量、图/摘要版本、权限传播与构建费用 |
| 多模态检索 | 表格、图示和版面是关键证据 | 页码、结构完整性、OCR 与视觉解析错误 |
| Query Rewrite / HyDE | 原查询难以匹配有效材料 | 改写是否丢失国家、时间、否定或业务限定 |

这些方法是候选实验，不是升级顺序。已有 SQL、CRM 或文档服务可以作为权威查询工具，不必全部重新复制到向量库。

## 定位失败，而不是只看总分

1. **没有有效材料**：业务知识缺失或过期，补知识或拒答。
2. **授权范围内未召回**：检查解析、切片、查询、索引和召回。
3. **召回但装配丢失**：检查重排、预算与压缩。
4. **证据充分但答案错误**：检查模型、Prompt、引用和推断。
5. **答案正确但动作错误**：检查业务状态、参数和权限，与检索指标分开。

测试集按文档、业务主体或时间隔离。同一政策的原题和改写题不能随机跨开发集与保留测试集。

## 版本化对照实验

固定文档、ACL、案例与模型，逐项比较切片、Hybrid、Rerank 和受限多轮检索。报告 Recall@K、引用支持率、正确拒答、权限泄露、延迟和单次有效任务成本。检索参数 K 的含义需注明是候选数还是最终装配数。

知识更新实验至少包含：新政策生效、旧政策撤销、用户撤权、图摘要残留、缓存残留以及无法定位原文的引用。

## 把知识应用与工具执行放在一起验收

[τ-Knowledge，2026](https://arxiv.org/abs/2603.04370)研究在多轮交互中协调非结构化政策、工具结果与业务状态变化。对客服系统，检索到相关条款只是中间条件，最终要判断是否对正确对象执行了允许的动作。

本项目可构造“条款允许催办，但订单仍缺材料”“条款适用于另一业务类型”“旧政策允许，当前政策禁止”等案例。分别检查证据是否正确、适用条件是否满足、动作是否经确认，以及独立读回是否符合预期；不能只以答案包含正确关键词给分。

本地 [authorized_chunks](../examples/core_patterns.py)验证权限与版本过滤逻辑；真实检索召回和生成效果仍需集成评测。
