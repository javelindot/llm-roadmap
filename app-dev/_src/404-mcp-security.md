协议连接成功只证明双方能交换消息。它不证明某个用户可以查询订单、运行脚本或提交写操作。

## 固定协议与实现两个版本

本轮核对的 MCP 最新规范为 **2026-07-28**。新版以请求元数据描述协议与客户端能力，旧版使用连接级 initialize。较早 SDK 的 ClientSession.initialize 和服务端 sampling 示例不能作为新版通信模型的证明。

迁移需要同时记录规范日期、客户端/服务端 SDK 版本、传输绑定和兼容模式。先跑请求、错误、通知、取消和重连契约测试，再切换流量；不能只替换协议日期字符串。

## 授权分三层

| 层次 | 检查 | 例子 |
|------|------|------|
| 服务连接 | 目标服务身份、传输与认证 | MCP 服务地址来自批准配置 |
| 委托权限 | 令牌受众、范围、有效期 | 令牌只用于指定资源服务 |
| 业务授权 | 租户、用户、对象、参数和状态 | 当前用户可查询这笔订单 |

HTTP 授权规范使用 OAuth 相关机制和受保护资源元数据。stdio 场景按宿主环境取得凭证，不应把 HTTP OAuth 流程机械移植过去。

scope 描述服务权限，但最终仍需对象级授权。访问令牌由可信运行时管理，不放进 Skill、模型上下文或 trace；也不能把接收的任意令牌直接透传给下游服务。

## 动态工具发现

工具身份应保留服务与工具名的组合，模型可见别名映射回原身份。工具定义改变后重新进行权限与 schema 检查；来自远程服务的 description 不是可信系统指令。

按需发现能减少工具定义开销，但发现流程不能扩大用户权限。恶意服务 URL、重定向、资源 URI 和网络访问应经过目标白名单及出站策略检查。

## MCP 与 A2A 的职责

| 机制 | 交换什么 | 典型用途 |
|------|----------|----------|
| Function Call | 模型提出的函数请求 | 应用内接业务执行器 |
| MCP | 工具、资源等服务能力 | 统一连接和能力发现 |
| Agent Skills | 方法、规则和资源文件 | 复用任务处理流程 |
| A2A | Agent 能力卡、消息、任务与产物 | 跨系统委托独立 Agent |

A2A 允许远程任务跟踪、流式更新和异步通知，客户端不必共享对方内部记忆。实际数据结构应以固定版本的规范与 SDK 为准。协议中的 Task 不自动等于本系统的 Case，必须记录关联与责任归属。

同进程的两个函数通常不需要跨 Agent 协议。需要跨团队、独立运行环境或权限域时，再衡量引入 A2A 的认证、恢复和观测成本。

## 异步与取消的业务边界

取消流或停止等待并不保证已经发出的外部动作被撤回。跨服务任务至少保存本地 Case/Run、远程任务 ID、操作幂等键、状态、结果来源和回执。

重连后查询既有任务；重复通知去重；验签并校验任务归属。未知写结果先对账，不能因为协议连接断开就判为未执行。

## 集成验收

覆盖错受众令牌、过期凭证、跨租户对象、同名工具、工具定义更新、未知协议版本、取消后迟到结果和重复 webhook。明确哪些测试由 SDK 执行，哪些由应用执行，避免两个层次都以为对方已经检查。
